### General & Architecture

#### What is C.O.P.P.E.R.?
C.O.P.P.E.R. (Centralized Omnifunctional Personal Productivity and Execution Routine) is an open-source, local-first personal AI desktop operating system. It coordinates local LLMs through Ollama, maintains persistent epistemic decaying memory, protects user security via the Guardian Safety Engine, and delivers a desktop HUD using React and Electron.

#### Does C.O.P.P.E.R. require an active internet connection?
**No.** Once models and dependencies are installed, C.O.P.P.E.R. runs 100% offline with zero network egress. All inferences, embeddings, voice synthesis, and safety evaluations execute on your local machine. This is verified by our automated socket egress test suite (`tests/security/test_offline_egress.py`).

#### Can I evaluate C.O.P.P.E.R. without downloading multi-gigabyte models?
**Yes.** Start the application with `COPPER_DEMO=1`:
```powershell
# Windows
$env:COPPER_DEMO="1"; python -m uvicorn app.main:app --app-dir backend --port 8000
```
In demo mode, the application uses mock conversational streams, seeded epistemic memories, and visual demonstrations without querying Ollama.

### Hardware & Models

#### What are the minimum and recommended hardware specifications?
- **Minimum (CPU Mode / Mini Models)**: 4 CPU cores, 16 GB RAM, 0 GB VRAM. (Uses `qwen2.5:1.5b` and `smollm2:1.7b`).
- **Recommended (GPU Workstation)**: 8+ CPU cores, 16 GB+ RAM, NVIDIA GPU with 8 GB+ VRAM (e.g., RTX 3060, 4060, 5060 Laptop or higher). Runs `qwen2.5:14b` at ~35 tokens/sec.
- **High-End Studio**: 16+ CPU cores, 32 GB RAM, 16 GB+ VRAM. Runs `deepseek-r1:14b` and `qwen2.5-coder:14b` with concurrent agent swarms.

#### Which local model backend is supported?
C.O.P.P.E.R. is built primarily for **[Ollama](https://ollama.com/)**. Pull your preferred models using:
```bash
ollama pull qwen2.5:14b
ollama pull qwen2.5-coder:14b
```

### Security, Safety & Privacy

#### How does Guardian prevent destructive terminal actions?
All commands generated by agents pass through Guardian's AST and regex safety filter (`backend/app/core/guardian.py`). Any destructive operations (`rm -rf /`, base64 execution chains, reverse shells, PTY spawns) are classified as **Level 2** (requires explicit modal confirmation) or **Level 3** (strictly blocked).

#### Where is my data stored?
All user data remains entirely within your local repository clone:
- Relational metadata & episodic logs: `data/copper.db` (SQLite)
- Semantic vector embeddings: `data/chroma/` (ChromaDB)
- User profile & preferences: `data/user_profile.json`

#### How do I wipe all stored data?
To reset all databases and memory collections to a pristine state, run:
```powershell
python scripts/wipe_data.py --all
```
or use `make wipe-data`.
