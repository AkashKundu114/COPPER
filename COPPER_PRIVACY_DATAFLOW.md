# C.O.P.P.E.R. Privacy Architecture & Dataflow Specification

**System:** C.O.P.P.E.R. Sovereign AI Operating System  
**Classification:** Strict Zero-Egress Local-First Architecture  
**Release Version:** 3.0.0  
**Effective Date:** October 16, 2026  

---

## 1. Zero-Egress Sovereignty Guarantee

C.O.P.P.E.R. is architected from the ground up as a **sovereign, air-gapped personal AI runtime**. Unlike cloud-reliant AI assistants, C.O.P.P.E.R. requires **zero external network egress** for its core intelligence, memory retrieval, speech synthesis, and tool execution.

### Key Privacy Principles:
1. **Local Model Execution:** All reasoning, routing, and tool generation are performed locally by models hosted via local Ollama (`127.0.0.1:11434`) or direct PyTorch/ONNX runtime.
2. **Local Vector & Graph Storage:** Episodic memories, semantic response caches, and knowledge graphs reside entirely on the local filesystem within `data/`.
3. **Disabled Telemetry:** Third-party telemetry collectors (including ChromaDB telemetry and OpenTelemetry cloud exporters) are disabled by default.
4. **Log Sanitization:** All credentials, API tokens, passwords, and private keys are scrubbed from system stdout and log files by the logging engine.

## 3. Storage Topology & Retention Policies

All persistent data generated by C.O.P.P.E.R. is housed strictly within the local host filesystem under `D:\C.O.P.P.E.R\data\`:

| Path | Data Type | Sensitivity | Retention & Purge Policy |
|---|---|---|---|
| `data/copper.db` | SQLite database: session chat history, scheduled tasks, background events | Medium | Persisted locally; cleared via UI settings or `DELETE /chat/history/{id}`. |
| `data/chroma/` | ChromaDB vector embeddings (cosine distance HNSW) | Medium | Local on-disk persistence. Telemetry explicitly disabled (`anonymized_telemetry=False`). |
| `data/profiles/active_user.json` | Sovereign user profile facts, role, hardware specs, preferences | High | Single-user sovereign storage. Sensitive pattern filter prevents secret ingestion. |
| `data/sessions_history.json` | Ephemeral chat turns partitioned by `session_id` | Medium | In-memory with JSON file backup; capped at last 50 turns per session. |
| `data/audio/cache/` | Generated WAV speech fragments | Low | Ephemeral disk cache; overwritten or pruned on session restarts. |
| `logs/copper.log` | Asynchronous application event log | Medium | Filtered via `RedactingFilter`; all API keys and credentials masked. |

## 4. Network Boundary & Loopback Bindings

The application listens strictly on private loopback addresses:
- **FastAPI Backend:** Bound to `127.0.0.1:8000` (refuses remote network interfaces).
- **Ollama Engine:** Bound to `127.0.0.1:11434`.
- **Electron IPC:** Uses `ipcRenderer` and `ipcMain` across private context-isolated memory bridges; no external remote debugging ports are exposed.
- **Vite Dev Server (Dev mode only):** Bound to `localhost:5173`. In production, Electron loads directly from disk via `mainWindow.loadFile("dist/index.html")`.

---

## 5. Third-Party Egress Audit

A code-level and network inspection of all outbound requests confirmed:
1. **ChromaDB:** Configured with `Settings(anonymized_telemetry=False)`. No telemetry beacons are transmitted.
2. **OpenTelemetry:** Tracing uses local in-memory trace contexts. Exporters do not connect to external SaaS collectors unless explicitly configured by the operator via environment variables.
3. **Web Search Tool:** The built-in `web_search` tool is strictly opt-in and triggered only when the operator explicitly requests external information (e.g. *"Search the web for..."*). When triggered, queries are executed via direct HTTP search scraping without passing user identity or profile facts.
