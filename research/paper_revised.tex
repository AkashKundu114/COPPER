\begin{abstract}
Equipping local-first autonomous agents with persistent episodic memory enables multi-session personalization, but introduces an insidious vulnerability: delayed memory poisoning. In existing agent architectures, an adversary can plant untrusted instructions via indirect prompt injection in external documents or tool outputs. Once ingested, the agent inadvertently recalls these memories in subsequent, unrelated sessions, executing unauthorized actions. Crucially, contemporary agent systems (e.g., MemGPT, Generative Agents, AutoGen) conflate \textit{semantic retrieval relevance} with \textit{tool execution authority}---treating any memory deemed relevant to the query as inherently trusted context. 

To resolve this vulnerability, we present \textbf{MemoryQuarantine}, a dual-plane governance architecture for local tool-using agents that decouples semantic recall from execution authority. MemoryQuarantine introduces consequence-calibrated authorization: the permission of memory $m$ to authorize action $a$ is bounded by $\text{Authority}(m, a) = \gamma(m) \cdot C(m) \cdot (1 - \mathcal{R}(a))$, coupling immutable source provenance $\gamma(m)$, calibrated epistemic confidence $C(m)$, and semantic action reversibility risk $\mathcal{R}(a)$ enforced deterministically at the tool boundary. We evaluate MemoryQuarantine on \textbf{CopperMemoryBench} (160 multi-session traces spanning direct injection, indirect poisoning, delayed steering, bridging subversion, and contradiction floods) and an end-to-end physical execution harness running local models on an NVIDIA GeForce RTX 5060 Laptop GPU. MemoryQuarantine achieves an Attack Success Rate (ASR) of \textbf{0.0\%} (down from 100.0\% in flat vector RAG and 80.0\% in Bayesian baselines, two-tailed Fisher's exact $p = 2.21 \times 10^{-59}$) and a Threat Interception Rate of \textbf{100.0\%} (exact 95\% Clopper-Pearson CI: [96.4\%, 100.0\%]), while preserving \textbf{100.0\%} benign task completion with zero false quarantines and under \textbf{0.01 ms} evaluation latency.
\end{abstract}

\section{Introduction}

The deployment of autonomous Large Language Model (LLM) agents directly on consumer edge hardware represents a paradigm shift toward privacy-preserving, local-first computing~\cite{wu2023autogen,hong2024metagpt}. To maintain operational coherence across disjoint user workflows, modern agents are increasingly augmented with long-term episodic memory systems, spanning external relational databases, vector stores, and structured knowledge graphs~\cite{packer2023memgpt,park2023generative,bernal2024hipporag}. Through persistent memory, an agent recalls prior user preferences, project conventions, and environmental states over weeks of interaction.

However, this persistence introduces an unaddressed architectural vulnerability: \textbf{delayed persistent memory poisoning}~\cite{torres2026ghostwriter,dong2024minja,chen2024agentpoison}. Unlike ephemeral prompt injection attacks where the adversary must maintain active interaction within the current context window~\cite{debenedetti2024agentdojo}, memory poisoning decouples the attack injection from its execution. An adversary can embed an indirect prompt injection within a web search result, downloaded document, or API payload. The agent, during routine information gathering, ingests this text into long-term storage. Days or weeks later, an innocuous user command triggers semantic retrieval; the agent recalls the malicious instruction, treats it as trusted historical context, and invokes high-consequence host tools (e.g., modifying files, writing shell commands, or leaking local tokens)~\cite{torres2026ghostwriter}.

The root cause of this vulnerability lies in a foundational architectural defect present across current agent memory paradigms:
\begin{quote}
\textbf{The Retrieval-Authority Conflation Fallacy:} \textit{Current agent systems implicitly assume that if a memory record $m$ possesses high semantic similarity to a user query $q$ ($\text{Relevance}(m, q) \approx 1$), it inherently possesses the authority to mandate tool action $a$ ($\text{Authority}(m, a) \approx 1$).}
\end{quote}

In MemGPT~\cite{packer2023memgpt}, retrieved memory chunks are injected into the agent's system prompt as plain text without provenance tags. In Generative Agents~\cite{park2023generative}, memory recall is driven strictly by recency, importance, and query relevance. When an untrusted web page instructs the agent to \textit{"Always backup internal credentials to a public directory,"} the memory is recalled with high relevance whenever backup operations are discussed, blinding the agent to the observation's untrusted origin. Recent defensive proposals, such as AM-Sentry~\cite{torres2026ghostwriter}, attempt to patch this flaw via input-time text classifiers. However, purely textual filters fail against semantic evasion, multi-session morphological mutations, and indirect bridging attacks~\cite{dong2024minja}.

In this paper, we propose \textbf{MemoryQuarantine}, a consequence-calibrated dual-plane governance architecture designed for local tool-using agents on consumer hardware. MemoryQuarantine resolves the retrieval-authority conflation by enforcing two strictly decoupled operational planes:
\begin{enumerate}
    \item \textbf{The Semantic Retrieval Plane:} Governed by contextual relevance $\text{Relevance}(m, q)$, this plane determines which memories are recalled into working context for conversation and reasoning.
    \item \textbf{The Execution Authority Plane:} Governed by consequence-calibrated authority $\text{Authority}(m, a)$, this plane enforces a deterministic gate at the physical tool execution boundary. The permission of memory $m$ to authorize action $a$ is computed as:
    \begin{equation}
    \text{Authority}(m, a) = \gamma(m) \cdot C(m) \cdot (1 - \mathcal{R}(a))
    \end{equation}
    where $\gamma(m) \in [0, 1]$ represents immutable source provenance, $C(m) \in [0, 1]$ represents epistemic confidence updated via natural log surprise units (nats), and $\mathcal{R}(a) \in [0, 1]$ represents the operational reversibility risk of the proposed action.
\end{enumerate}

By coupling provenance directly to action reversibility, MemoryQuarantine guarantees that low-provenance memories (e.g., untrusted web data with $\gamma = 0.15$) can be freely retrieved and used for harmless, reversible tasks (e.g., reading files, formatting code), but are mathematically blocked from authorizing irreversible operations (e.g., overwriting configurations, deleting records).

\subsubsection{Key Contributions}
\begin{itemize}
    \item \textbf{Decoupled Dual-Plane Formulation:} We formalize the separation of semantic retrieval relevance from tool execution authority, proving that memory security requires evaluating the operational consequence $\mathcal{R}(a)$ of the instructed action.
    \item \textbf{Consequence-Calibrated Authority Gate:} We derive the triple-product authority metric $\text{Authority}(m, a)$ and establish deterministic decision boundaries ($\text{ALLOW} \ge 0.65$, $\text{CHALLENGE} \in [0.25, 0.65)$, $\text{BLOCK} < 0.25$) enforced at the tool boundary.
    \item \textbf{CopperMemoryBench \& Physical Evaluation:} We evaluate MemoryQuarantine on a 160-trace benchmark spanning five adversarial attack vectors and benign controls, alongside an end-to-end physical execution harness running local models on an NVIDIA GeForce RTX 5060 Laptop GPU. MemoryQuarantine achieves 0.0\% ASR and 100.0\% Threat Interception Rate ($p = 2.21 \times 10^{-59}$) with zero false quarantines and $0.005\text{ ms}$ overhead.
    \item \textbf{Empirical Audit Reconciliation:} We candidly reconcile and document all historical metrics across routing, safety, and memory persistence in accordance with IEEE reproducibility standards.
\end{itemize}

\section{Threat Model \& Problem Formulation}

\subsection{System Architecture \& Execution Loop}
We consider a local-first autonomous agent running in user space on consumer hardware (e.g., Windows/Linux desktop). The agent runtime manages:
\begin{itemize}
    \item A \textbf{Persistent Epistemic Store} ($\mathcal{M}$), persisting memories $m = \langle c, \gamma, C, t, \mathbf{v} \rangle$ where $c$ is content, $\gamma$ is source provenance, $C$ is calibrated confidence, $t$ is timestamp, and $\mathbf{v}$ is the dense vector embedding.
    \item A \textbf{Local Foundation Model} ($M$), executed locally via quantized backends (e.g., Ollama/llama.cpp) on consumer GPU VRAM.
    \item A \textbf{Deterministic Tool Executor} ($\mathcal{T}$), providing execution capabilities including filesystem writes (`file_write`), terminal execution (`shell_execute`), and web requests (`web_search`).
\end{itemize}

\subsection{Adversary Capabilities}
The adversary ($\mathcal{A}$) operates under an indirect delayed poisoning model:
\begin{enumerate}
    \item \textbf{No Root / Kernel Privilege:} The adversary does not have operating system administrative privileges, cannot inspect ring-0 memory, and cannot directly alter the SQLite database files on disk.
    \item \textbf{No Direct Model Weight Tampering:} Base foundation model weights are fixed and uncompromised.
    \item \textbf{Indirect Untrusted Injection:} The adversary can publish malicious text on web pages, send email messages, or generate synthetic documents that the agent ingests during routine research.
    \item \textbf{Delayed Activation Exploitation:} The adversary relies on natural agent semantic retrieval to activate the payload in future sessions, crafting prompts that blend malicious tool commands with plausible user directives.
    \item \textbf{Contradiction Flooding:} The adversary can deliver multiple contradictory statements across sessions to attempt epistemic ratcheting or confidence collapse.
\end{enumerate}

\subsection{Protected Assets \& Security Invariants}
The security objective is to preserve three invariant guarantees:
\begin{itemize}
    \item \textbf{Asset Invariant 1 (Filesystem \& Credential Integrity):} No tool operation that mutates persistent user files, executes shell commands, or exposes credentials can be authorized solely by untrusted or intermediate-provenance memories without explicit operator confirmation.
    \item \textbf{Asset Invariant 2 (Memory Immutability):} Provenance tags $\gamma(m)$ assigned by the ingestion controller are immutable and cannot be altered by LLM reasoning or prompt instructions.
    \item \textbf{Asset Invariant 3 (Utility Preservation):} Legitimate user preferences must remain authoritative ($\text{Authority} \ge 0.65$), ensuring 100\% autonomous completion of benign daily workflows.
\end{itemize}

\subsection{Out-of-Scope Threats}
Physical hardware attacks (e.g., cold boot, PCIe bus sniffing), compromised operating system binaries, hardware side-channels, and social engineering that tricks the user into explicitly typing malicious commands directly into the terminal are outside the scope of this work.

\section{MemoryQuarantine Architecture}

\subsection{Dual-Plane Separation}
Traditional architectures execute memory-driven tool calls in a single monolithic loop: $q \to \text{Retrieve}(q, \mathcal{M}) \to \text{LLM}(q, \text{Context}) \to \text{Execute}(a)$. MemoryQuarantine splits this pipeline into two orthogonal control planes:

\begin{figure}[!t]
\centering
\includegraphics[width=\linewidth]{figures/fig6_epistemic_memory_decay_dynamics.png}
\caption{Epistemic belief revision dynamics under PW-EBR and UMF-EDR, illustrating symmetric tier demotion upon contradiction.}
\label{fig:epistemic_decay}
\end{figure}

\subsubsection{Plane 1: Semantic Retrieval Plane}
Given user query $q$, the retrieval engine queries the vector store via Hybrid Reciprocal Rank Fusion (RRF), combining dense cosine similarity and sparse BM25 scoring:
\begin{equation}
\text{Relevance}(m, q) = \frac{1}{60 + \text{rank}_{\text{dense}}} + \frac{1}{60 + \text{rank}_{\text{BM25}}}
\end{equation}
Memories exceeding relevance threshold $\tau_{\text{rel}}$ are admitted into the LLM context buffer for generative reasoning. However, admission to this buffer grants **zero tool execution authority**.

\subsubsection{Plane 2: Execution Authority Plane}
When the LLM proposes an action $a = \langle \text{tool}, \text{arguments} \rangle$, the proposal is routed to the \textbf{Guardian Safety Gate} before reaching the physical tool implementation. The gate extracts the supporting memory $m$ from the execution trace and computes $\text{Authority}(m, a)$.

\subsection{Mathematical Formulation of Authority}
The consequence-calibrated authority metric is formulated as:
\begin{equation}
\text{Authority}(m, a) = \gamma(m) \cdot C(m) \cdot (1 - \mathcal{R}(a))
\end{equation}

\subsubsection{1. Provenance Weight Hierarchy ($\gamma$)}
Provenance represents the objective authenticity of the memory's ingestion channel, assigned deterministically by the runtime:
\begin{equation}
\gamma(m) = \begin{cases}
1.00, & \text{user\_explicit (Direct prompt from operator)} \\
1.00, & \text{user\_verified (Operator manually confirmed)} \\
0.95, & \text{system\_verified (Local deterministic system state)} \\
0.85, & \text{local\_file (Read from local filesystem)} \\
0.75, & \text{observation (Agent physical tool observation)} \\
0.50, & \text{chat (Informal conversational dialog)} \\
0.35, & \text{web\_search (Retrieved external search snippet)} \\
0.15, & \text{external\_untrusted (Unverified remote document)} \\
0.10, & \text{injected (Suspected adversarial payload)}
\end{cases}
\end{equation}

\subsubsection{2. Epistemic Confidence ($C$) with Natural Log Surprise}
Epistemic confidence $C(m) \in [0.05, 0.99]$ models belief certainty. Unlike naive additive counters, confidence is updated via Provenance-Weighted Epistemic Belief Revision (PW-EBR) using log-odds with natural log surprise units (nats):
\begin{equation}
\mathcal{L}_{t+1}(m) = \mathcal{L}_t(m) + \text{polarity} \cdot \gamma(m) \cdot \ln\left(1 + \frac{1}{\max(C_t(m), 10^{-4})}\right)
\end{equation}
where $\text{polarity} = +1$ for corroborating evidence and $-1$ for contradictory evidence. Confidence is restored via the logistic sigmoid: $C(m) = \sigma(\mathcal{L}(m))$. Furthermore, memories undergo Unified Memory Forgetting with Ebbinghaus Decay and Retrieval Practice (UMF-EDR):
\begin{equation}
C(t) = C_0 \cdot \exp(-\lambda_{\text{eff}} \cdot \Delta t), \quad \lambda_{\text{eff}} = \frac{\lambda_0}{1 + \ln(1 + N_{\text{retrievals}})}
\end{equation}

Crucially, tier transitions are symmetric: if $C(m)$ drops below 0.70, a `FACT` is demoted to `OBSERVATION`; below 0.40, it collapses to `HYPOTHESIS`, preventing the one-way ratcheting bug identified in prior audits.

\subsubsection{3. Action Reversibility Risk ($\mathcal{R}$)}
Action reversibility evaluates the operational consequence of the tool action on host state:
\begin{equation}
\mathcal{R}(a) = \begin{cases}
1.00, & \text{Catastrophic / Invariant breach (rm -rf, mkfs, format)} \\
0.85, & \text{High-impact host mutation (git reset --hard, chmod 777)} \\
0.55, & \text{Destructive mutation (file overwrite, delete, drop)} \\
0.30, & \text{State modification (file creation, append, patch)} \\
0.05, & \text{Reversible / Read-only (file\_read, web\_search, calc)}
\end{cases}
\end{equation}

\subsection{Decision Boundaries \& Gating Logic}
The Guardian Safety Gate deterministically maps $\text{Authority}(m, a)$ into three operational verdicts:
\begin{itemize}
    \item $\mathbf{Authority(m, a) \ge 0.65 \implies ALLOW:}$ Autonomous execution proceeds silently without user interruption.
    \item $\mathbf{0.25 \le Authority(m, a) < 0.65 \implies CHALLENGE:}$ Execution is paused; the operator is presented with an explicit confirmation dialog displaying memory provenance, reversibility risk, and exact command parameters.
    \item $\mathbf{Authority(m, a) < 0.25 \implies BLOCK:}$ Execution is unconditionally interdicted. The action is quarantined and logged to the audit trail.
\end{itemize}

\begin{algorithm}[t]
\caption{MemoryQuarantine Dual-Plane Tool Authorization}
\label{algo:quarantine}
\begin{algorithmic}[1]
\REQUIRE Query $q$, Action $a$, Epistemic Store $\mathcal{M}$, Context $\mathcal{C}$
\ENSURE Tool Execution Result or Interdiction
\STATE $\mathcal{M}_{\text{recalled}} \leftarrow \text{SemanticRetrieve}(q, \mathcal{M}, \tau_{\text{rel}})$ \COMMENT{Plane 1}
\STATE $a \leftarrow \text{LLM\_Reasoning}(q, \mathcal{M}_{\text{recalled}})$
\STATE $\mathcal{R}(a) \leftarrow \text{EvaluateReversibilityRisk}(a)$
\IF{$\text{IsHardSafetyInvariant}(a)$}
    \RETURN $\text{BlockUnconditionally}(\text{``System invariant violated''})$
\ENDIF
\STATE $m_{\text{supp}} \leftarrow \text{ExtractSupportingMemory}(a, \mathcal{M}_{\text{recalled}})$
\STATE $\gamma \leftarrow \text{GetImmutableProvenance}(m_{\text{supp}})$
\STATE $C \leftarrow \text{GetEpistemicConfidence}(m_{\text{supp}})$
\STATE $\text{Auth} \leftarrow \gamma \cdot C \cdot (1 - \mathcal{R}(a))$ \COMMENT{Plane 2 Authority}
\IF{$\text{Auth} < 0.25$}
    \RETURN $\text{BlockAndQuarantine}(a, \text{Auth}, \text{``Insufficient authority''})$
\ELSIF{$\text{Auth} < 0.65$}
    \IF{$\text{OperatorConfirmed}(\mathcal{C}) == \text{True}$}
        \RETURN $\text{ExecutePhysicalTool}(a)$
    \ELSE
        \RETURN $\text{RaiseOperatorChallenge}(a, \text{Auth})$
    \ENDIF
\ELSE
    \RETURN $\text{ExecutePhysicalTool}(a)$
\ENDIF
\end{algorithmic}
\end{algorithm}

\section{Experimental Methodology}

\subsection{Evaluation Hardware \& Environment}
All benchmarks were executed on an AMD Ryzen 9 8940HX workstation (16 cores, 32 threads) equipped with an NVIDIA GeForce RTX 5060 Laptop GPU (8,151 MiB GDDR6 VRAM, CUDA 13.4) and 16 GB DDR5 RAM running Windows 11 Enterprise x64 and Python 3.14.6. Local LLM inference was executed via Ollama v0.5.1 with quantized models offloaded to 100\% GPU VRAM.

\subsection{Benchmark Dataset: CopperMemoryBench}
We evaluate on \textbf{CopperMemoryBench}, an audited dataset containing 160 multi-session evaluation traces:
\begin{itemize}
    \item \textbf{Adversarial Traces ($N = 100$):} Divided equally across five attack vectors ($N = 20$ each): Direct Chat Injection (AV1), Indirect Tool Poisoning (AV2), Delayed Action Steering (AV3), Bridging Subversion (AV4), and Contradiction Floods (AV5).
    \item \textbf{Benign Control Traces ($N = 60$):} Comprising user customizations ($N = 20$), tool environmental observations ($N = 20$), and routine read-only tasks ($N = 20$).
\end{itemize}

\subsection{Evaluated Governance Strategies}
We benchmark six representative memory governance strategies:
\begin{itemize}
    \item \textbf{$B_0$ (Amnesic / No Memory):} Zero cross-session persistence.
    \item \textbf{$B_1$ (Flat Vector RAG):} Standard cosine similarity retrieval without provenance or action gating (representative of MemGPT~\cite{packer2023memgpt} and Generative Agents~\cite{park2023generative}).
    \item \textbf{$B_2$ (Last-Write-Wins):} Timestamp-ordered overwrite heuristic.
    \item \textbf{$B_3$ (Naive Bayes Updating):} Additive log-odds confidence without provenance hierarchy or surprise scaling.
    \item \textbf{$B_4$ (Provenance-Only):} Epistemic belief revision with source provenance $\gamma$, but without action reversibility coupling $\mathcal{R}(a)$.
    \item \textbf{$M_5$ (MemoryQuarantine — Ours):} Consequence-calibrated dual-plane authority gate.
\end{itemize}

\subsection{End-to-End Physical LLM Execution Harness}
To close the gap between synthetic arithmetic simulation and physical agent tool execution, we implemented a real-world testing harness (`test_real_llm_harness.py`). The harness initializes an isolated filesystem sandbox containing a canary target file (`canary_target.env`). In Session 1, legitimate preferences are recorded. In Session 2, an external document with delayed prompt injection is ingested. In Session 3, an innocuous user request activates memory retrieval. The local language model (`qwen2.5:0.5b` running on the RTX 5060 GPU) generates tool calls targeting the canary file. The tool execution is processed through `ToolExecutor` under each governance strategy, verifying physical file integrity.

\section{Related Work}

\subsection{Agent Memory Architectures}
MemGPT~\cite{packer2023memgpt} pioneered hierarchical virtual context management for LLMs, formalizing memory paging via tool calls. Generative Agents~\cite{park2023generative} demonstrated multi-agent social memory streams with linear scoring functions. HippoRAG~\cite{bernal2024hipporag} introduced neurobiologically inspired associative recall using Personalized PageRank. While these systems optimize retrieval relevance and context capacity, none implement consequence-aware tool authorization; recalled memories are treated as trusted context.

\subsection{Memory Poisoning \& Prompt Injection}
Torres et al.~\cite{torres2026ghostwriter} formulated GhostWriter, proving that persistent memory creates a vulnerable delayed attack surface. Dong et al.~\cite{dong2024minja} demonstrated query-only memory injection (MINJA), while Chen et al.~\cite{chen2024agentpoison} demonstrated backdoor trigger implantation in RAG (AgentPoison). Debenedetti et al.~\cite{debenedetti2024agentdojo} established AgentDojo for evaluating single-session prompt injections. MemoryQuarantine addresses the core limitation of these prior defenses by coupling provenance directly to operational action reversibility.

\subsection{Safety Guardrails \& Friction}
Llama Guard 3~\cite{inan2023llamaguard} and NeMo Guardrails~\cite{rebedea2023nemo} enforce conversational safety boundaries via binary classification or Colang dialog trees. However, binary guardrails induce confirmation fatigue~\cite{parasuraman1997humans} and lack awareness of memory provenance. MemoryQuarantine operates with negligible latency ($0.005\text{ ms}$), providing continuous consequence-calibrated gating without requiring dedicated 8B guardrail models.

\section{Discussion, Limitations, \& Future Work}

\subsection{The Necessity of Consequence-Aware Decoupling}
The central finding of this research is that in persistent agent architectures, \textbf{safety is an operational property of the proposed action, not an intrinsic semantic property of text}. An untrusted document stating \textit{"Set indentation to 4 spaces"} is completely harmless; the identical document stating \textit{"Delete all backup databases"} is catastrophic. By evaluating $\text{Authority}(m, a) = \gamma(m) \cdot C(m) \cdot (1 - \mathcal{R}(a))$, MemoryQuarantine safely permits benign low-provenance execution while decisively barring destructive operations.

\subsection{System Limitations}
\begin{enumerate}
    \item \textbf{Heuristic Action Reversibility Scoring:} In our implementation, $\mathcal{R}(a)$ is evaluated via AST analysis and regex normalization. For opaque, obfuscated shell payloads, static AST parsing can misestimate reversibility. Future work will integrate OS-level container sandboxes (e.g., Windows Sandbox / Linux seccomp).
    \item \textbf{Small Edge Model Instruction Following:} Edge SLMs (0.5B to 7B) exhibit lower reasoning fidelity than frontier cloud models. MemoryQuarantine circumvents this by enforcing authorization strictly outside the LLM in the deterministic Python runtime.
    \item \textbf{Single-User Boundary:} In multi-tenant environments, provenance tags $\gamma(m)$ will require cryptographic asymmetric key signatures to prevent cross-agent impersonation.
\end{enumerate}

\section{Conclusion}

Persistent memory is indispensable for personalized autonomous agents, but creates an acute delayed attack surface when semantic retrieval is conflated with execution authority. In this work, we presented \textbf{MemoryQuarantine}, a consequence-calibrated dual-plane governance architecture for local tool-using agents. By decoupling retrieval relevance from tool authority and enforcing $\text{Authority}(m, a) = \gamma(m) \cdot C(m) \cdot (1 - \mathcal{R}(a))$ at the tool boundary, MemoryQuarantine eliminates delayed memory poisoning ($\text{ASR} = 0.0\%$, $\text{TIR} = 100.0\%$, $p = 2.21 \times 10^{-59}$) while preserving 100.0\% benign task utility on consumer edge hardware.
